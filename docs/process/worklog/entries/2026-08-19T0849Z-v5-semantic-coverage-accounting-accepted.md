# V5 semantic coverage accounting accepted

The Navigator accepted CV18.DS3's strict semantic coverage accounting over the
generated non-sharded V5 authority/lifecycle, reminder-timer, and Git ambiguity
campaigns. Reports derive only from public Petrus v4 expanded operations,
passed independent checker results, detached observations, terminal
dispositions, and exact replay results. They are bounded deterministic strict
JSON with explicit artifact/profile/checker compatibility identities and no
percentage score.

A dimension now requires one complete checkpoint witness: its executable
adapter, relevant passed checker at that boundary, and detached semantic outcome
must coexist in one scenario. The campaigns mechanically evidence authority and
lifecycle movement, duplicate delivery, timer arm/maturity/acknowledgement,
provider response loss, selected crash/reconstruction cuts, conversation,
coding, Git mutation, explicit `FaultM` → `Pushed` recovery, fair convergence,
checker activation, and exact replay. CI rerun/repair, agent-terminal fault
cuts, stale or rate-limited reads, and remaining History/Dispatch cuts retain
exact blocked reasons and revisit triggers.

Slice-boundary review found that the first implementation could combine an
earlier checker pass with a later failing operation. A real terminal
checker-failure regression reproduced that false claim. Coverage now keeps
checkpoint-scoped certified prefixes: the failed duplicate boundary remains
uncovered, while the equivalent passing duplicate boundary is covered and
valid evidence completed before an unrelated later failure remains available.

`scripts/check full` passed 1,251 Python tests, 44 media tests, nine webhook
relay tests, lint/format/type/architecture checks, and source/wheel builds.
Production behavior is unchanged, the report reads no Petri marking or
production decision fold, and sharded V5 remains excluded. CV18.DS3 remains
Active for the blocked adapters, broader generated combinations, and later DS4
campaign retention and operations.
