# Pi workspaces reach canonical publication proof

Hamsterdan now pins Petrus exactly to
`750c4321bb51563666ce43e88f753ebe1f068520`. Each A2 start carries a canonical
archive of the requested PR head, its verified digest, bounded route/PR
correlation, and immutable per-operation policy. Schema-2 replay conflicts on a
different workspace, correlation, prompt, or effective policy before authority.

The host clones and exports only stage-zero regular blobs into a private bounded
root. Review and conversation receive read/search only. Coding additionally
receives Petrus's attachment-scoped workspace-root write grant; shell, GitHub,
credentials, host-tree mutation, `.git`, and `.petrus-hands-stage` are excluded.

After aggregate settlement, the receiver rejects malformed, noncanonical,
oversized, duplicate, traversing, absolute, linked, special, control, or
unsupported-mode archive entries. It stages regular additions, modifications,
deletions, and executable modes, force-includes safe ignored additions, derives
one indexed binary patch, and reproduces the exact result tree against a second
checkout of the requested head. Model diff and file claims are replaced rather
than trusted. Temporary stages are removed on success and failure; uncertain
removal fails closed.

Current authority is rechecked after workspace preparation, after agent work,
and at publication. The existing publisher reapplies the patch to the exact
head, performs fresh PR reads, recovers by stable operation and payload digest,
and advances by exact CAS. Reserved model-authored publication trailers are
rejected.

Focused suites passed 151 tests. `scripts/check full` passed formatting, Ruff,
ty, nine Bun relay tests, source and wheel builds, and 316 Python tests; the one
explicit provider test remained skipped. No credential lookup, authority
materialization, provider call, paid/live work, subscription, or extra usage ran.

The Local process-death and no-exactly-once limits remain. Receiver fetch is
time-bounded but not transfer-byte-quota bounded before tracked-tree admission;
workspaces themselves are bounded to 20,000 entries, 64 MiB expanded content,
1,000 changed paths, and a 4 MB patch.
