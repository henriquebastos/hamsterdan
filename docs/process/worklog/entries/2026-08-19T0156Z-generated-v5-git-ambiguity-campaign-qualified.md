# Generated V5 Git ambiguity campaign qualified locally

CV18.DS3 now drives a trusted-human change through the real non-sharded V5
HostService conversation, coding, mutation, crash/reconstruction, and canonical
History paths while modeling only external Git provider truth. One ref CAS is
accepted and its response and immediate proof are lost. V5 records `FaultM`,
remains not ready after the resulting head is admitted, and recovers only after
an admitted human comment names the exact operation. Lookup-first recovery then
records `Pushed` without a second ref update and converges under Petrus's fair
phase.

The independent model binds the change to the original full authority and
declared result head. The checker compares modeled acceptance and explicit
recovery provenance with the complete canonical `FaultM` → `Pushed` request and
terminal sequence. Deliberately removing the admitted recovery grant or
corrupting the recovered terminal head proves that plausible-looking History is
not accepted without independent external authorization and result truth.

A fixed crash vertical and a focused campaign with four explicit semantic
anchors plus five deterministic generated schedules cover definite response,
response loss, crashes before delivery, after acceptance, and after new-head
admission, plus old-delivery redelivery. Every successful expanded schedule
replays exactly as a Petrus v4 artifact. Slice-boundary review found the missing
recovery-provenance check and the implementation was remediated before
acceptance.

`scripts/check full` passed 1,246 Python tests, 44 media tests, nine webhook
relay tests, lint/format/type/architecture checks, and source/wheel builds. The
production application still constructs `HostGitPublisher` by default; only the
DST composition injects modeled Git truth. CV18.DS3 remains Active for broader
fault vocabulary, semantic coverage reporting, and campaign operations; real
Git and process evidence remains complementary DS4 scope.
