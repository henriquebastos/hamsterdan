# CV3.DS2 — Authority and collaboration gates

Prove strict stale-base update, true merge conflict resolution, review request,
changes requested, required approval, unresolved review thread, and draft to
ready transitions through real GitHub state on isolated PRs. No scenario-control
file may stand in for provider authority.

## Delivered local slice

GitHub remains the authority. Hamsterdan continues to fold provider state into
its existing minimal base, review, conversation, mergeability, conflict, and
lifecycle facts; no provider object, policy engine, place, transition, or
Activity was added to the Net.

Characterization exposed and corrected two host-boundary defects. GitHub login
comparison now excludes author approvals case-insensitively, and reversible
provider observations such as clean → conflict → clean receive a fresh durable
identity only when their normalized facts differ from current Control. The
second correction is restart-qualified and exact repeated polls remain inert.

The read-only `inspect-authority` operator command records one stable,
revalidated GitHub basis. It fails closed on indeterminate mergeability,
potentially incomplete bounded rules/review/thread collections, malformed
policy, or a head/base change during collection. Required approval is proven by
GitHub's GraphQL `reviewDecision`, not by Hamsterdan recreating reviewer
eligibility. Review prose, thread text and identifiers, raw provider objects,
and credentials remain excluded.

## Remaining live acceptance

Fresh same-repository PRs targeting a dedicated authority base must prove draft
to ready, requested review, changes requested, required approval, unresolved
thread resolution, strict stale-base update, and true conflict resolution. The
dedicated branch owns a one-approval, strict-check, thread-resolution ruleset so
accepted `main` PR evidence is not reprojected. Scenario-control files remain
unchanged. One separately reviewed base-advance PR is the only planned merge;
Hamsterdan never merges a demonstration PR.
