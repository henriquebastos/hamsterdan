# CV20.DS12 — Qualify journeys and real-seam correspondence

## Outcome

Qualify the complete non-selectable replacement as one coherent system. Run the
accepted journey portfolio through production owners and deterministic
composition; pair each material simulation claim with direct provider, Git, Pi,
SQLite/filesystem, OS-process or concurrency evidence; and emit one bounded,
revision-bound qualification report for the DS13 cutover decision.

DS12 is not a late integration phase. Every earlier tracer already owns local/
cross DST, observability, bounds and its first applicable correspondence. This
story closes portfolio combinations, distribution and real-process evidence.

## Qualification path

```text
declared journey/schedule
  -> non-selectable production host and all real owners
  -> named input/effect/recovery/lifecycle outcome
  -> owner-local plus cross checker reports
  -> exact fresh-object replay and finite resource evidence
  -> mapped real-seam correspondence rows
  -> revision/dependency-bound qualification report
```

No new major effect family, custody model, authority policy or concurrency
dimension may be hidden here. A discovered gap returns to its owning tracer or
requires Navigator approval to split another tracer before DS12 can close.

## Component Technical Stories

1. Encode the complete journey declarations and visible outcome vocabulary.
2. Add finite schedule generation, semantic shrinking and coverage accounting.
3. Complete correspondence harnesses for GitHub transport/Git, Pi/workspace,
   fresh storage, process death, leases and bounded multi-PR concurrency.
4. Add revision/dependency/fixture/resource/secret/distribution evidence report.
5. Run the complete source/test disposition and active-name pre-cutover census.

## Required journey portfolio

The top-level journeys are:

1. clean green PR;
2. first-attempt CI flake and one rerun;
3. persistent CI regression and bounded repair/escalation;
4. seeded review finding;
5. authorized conversational change;
6. agent repair;
7. clean/hero review;
8. draft to ready;
9. stale base update;
10. true conflict resolution;
11. collaboration approval; and
12. causal exact-delivered-result mutation publication.

Reminder/timer progression, route revocation, accepted-hidden Git/provider
recovery, PR closure/merge, known-subject exact-read convergence,
unknown-open-PR discovery and known/discovery-turn fairness are required
overlays on every applicable journey rather than separate toy models.

## Fixed design

- Journeys call public production owners and root composition. They do not
  inspect private stores, patch hidden runtime state or fabricate terminals.
- Each journey declares initial state, external/operator input, visible outcome,
  authority, stable operations, physical effect cardinality, crash cuts and
  finite bounds.
- Generated schedules have finite operation/interleaving/fault domains. A
  shrunk case preserves the same semantic violation and exactly replays.
- Every material deterministic claim maps to a correspondence row with claim,
  real seam, fixture, expected observation, bound and known limit.
- GitHub uses real SDK/HTTP transport against mock transport by default; live
  provider mutation and authenticated Pi require separate explicit approval.
  Missing approval is reported as unavailable and blocks claims that require it.
- Durability evidence uses fresh connections/handles and OS process death, not
  only in-process exception/reconstruction.
- Physical attempts/acceptances are asserted independently from terminal count.
- Evidence is machine-readable and bound to revision, dependency versions,
  scenario, fixture identity, limits, resources and result.
- Secret scans cover arguments, bounded environment projections, logs, stores,
  artifacts, workspaces and agent values without printing secrets.
- The replacement stays disabled/non-selectable and never reads current state.
- Discovery correspondence covers configured scope, list/get pairing,
  pagination/rate metadata, `RepositoryDiscoveryPassBoundary`, page restart or
  ruled ETag continuation, exact-read-before-registration, list-absence safety,
  webhook races, finite rate reserve/defer behavior and DST scheduling. It makes
  no atomic completeness claim.

## API-strengthening checkpoint

Review the qualification command and report consumer together, then settle:

- journey/schedule/overlay declaration and stable identifier vocabulary;
- setup/input/cut/restart/effect/posture/bound expectation DSL;
- shrink and “same semantic violation” contract;
- local, cross, resource, coverage and portfolio report schemas;
- correspondence claim/fixture/pass/fail/unavailable vocabulary;
- subprocess launch/cut/kill/reopen and physical-attempt observation protocol;
- revision/dependency/artifact binding, byte limits and evidence storage; and
- ordinary-CI versus separately approved live-qualification command surfaces.

Write the ruled qualification API into [the API contract](api-contracts.md).
Real-owner execution, complete visible evidence, explicit unavailability,
physical counts, fresh-process recovery and separate external approvals are fixed.

## Tracer acceptance

All twelve journeys and overlays pass through production owners with exact
replay, meaningful local/cross sensitivity, finite generation/shrinking,
declared resource peaks and no hidden skip. Every required claim has accepted
correspondence or an explicit blocker that prevents DS12 acceptance.

The report includes real Git object/ref CAS and accepted-hidden lookup, real SDK
transport, fresh SQLite/filesystem transaction cuts, OS process kills at named
cuts, lease expiry, bounded concurrent PRs, Pi protocol/workspace/cleanup, and
configured-repository discovery/list/get/DST evidence. Authenticated Pi remains
subject to separate approval. Source/wheel, CLI, disabled service, architecture,
active-name and secret checks pass on the exact revision.

## Done condition

The complete system behavior and correspondence portfolio is accepted and
understandable from CV20 plus its evidence report. DS12 cannot pass by aggregating
locally green components or by deferring an applicable real seam to DS13.

## Stop conditions

Stop if a journey needs a second model/private hook, a new major capability is
discovered, shrinking changes the failure meaning, process recovery is only
simulated, a required correspondence row is silently skipped, physical counts
are unavailable, or qualification would enable the replacement.

## Rollback

Remove incomplete qualification harness/evidence and temporary fresh fixtures.
Accepted DS1–DS11 production behavior remains non-selectable; never mutate or
translate current runtime state.

## Validation

Run all journeys/overlays, generated schedules/shrinking, exact replay,
local/cross/resource/coverage reports, real transport/Git/Pi/storage/process/
lease/concurrency correspondence as approved, source/wheel/CLI checks, full
quality gates, active-name census and secret scan.

## Expansion boundary

Expand by journey family or real seam and risk. Every credential, live mutation,
process kill and cleanup action retains explicit approval. No child may weaken a
previous tracer's acceptance or turn DS12 into component-first integration.
