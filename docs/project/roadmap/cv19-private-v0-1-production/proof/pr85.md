## 1c. Open findings

### 1c1. Status reply claimed an approval before human approval

[Reply 5590581614](https://github.com/HBNetwork/demo-pr-readiness/pull/85#issuecomment-5590581614)
said: “Human review shows approval and a changes-requested review.” The saved
GitHub snapshot contains no approved review at that checkpoint.

The host's `approval` gate means the repository approval requirement is
satisfied. With zero required approvals and no outstanding requested reviewer,
that flag can be true without an approved review. Conversation context passes
the flag to the agent, which rendered it as an actual approval. The separate
changes-requested gate correctly prevented readiness until Cris approved.
The misleading wording remains unfixed; gate satisfaction and observed review
approval need distinct meaning in the status response.

### 1c2. An older Pi cleanup record causes shutdown errors

Stopping the prior release and restarting the new release both emitted
`RuntimeProtocolError: host-cleanup-uncertain` followed by application shutdown
failure. The new release returned healthy after the supervised restart.

One pre-existing settled operation has indeterminate outcome and unverified
cleanup. Petrus's Pi host close path checks cleanup evidence across retained
ledger records, so this older record makes aggregate cleanup uncertain. Before
PR85, the ledger contained 90 clean operations and one unverified operation;
after PR85 it contained 100 clean operations and the same unverified operation.
All ten new Pi operations cleaned up successfully. The older record was
preserved, and the shutdown defect remains unresolved.

These findings are open verification results. Neither has been accepted as
deferred debt or fixed by this deployment.
